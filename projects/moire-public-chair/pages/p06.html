5. Pattern Encoding and Fabrication Workflow

How an image is hidden in the rear grating, and how the grating is turned into a file a laser cutter can read.

5.1Encoding

The image is stored as a sideways shift of the rear slots.

Chair A keeps straight slots. In Chair B every slot is shifted by φ(x, y) of a period: a point of B is open where frac(−u/pA − φ) < ½. Regions with φ = 0 and φ = ½ appear in opposite tones; walking adds the same shift everywhere, so the regions invert in turn.

5.2Patterns

Three images, three ways of using phase.

Hexagonal ripple (70 mm cells): phase grows outward, so rings travel as you walk. Cubes (100 mm): faces at 0, ⅓ and ⅔, so the faces take turns being bright. MOORE: letters at ½, background at 0, so the word flips. Edges are softened over about one period, so slots bend rather than break.

5.3Workflow

Six scripted steps turn a picture into a cut file.

Written in Python (NumPy, SciPy, scikit-image, Shapely, ezdxf, rhino3dm) through conversation with an AI model. I set the design rules, judged every result and decided when it was right; the AI wrote and debugged the code. A new image becomes a new set of cut files in a few minutes.

5.4Checks

Two failures shaped the method; three checks close it.

Smoothing the wrapped phase created false seams; smoothing it as vectors created vortices at tile corners. Smoothing the unwrapped phase removed both. Final files: no detached pieces, every slot and bar ≥ 4 mm, and the simulated view reproduces the image.
